# RoboHood 제조업 중심 기획서 v1

> 제조현장의 데이터 수요와 수집 수행팀을 연결하고, 청년 Physical AI 현장 전문인력이 교육·직무 범위에 맞춰 유급 수집 업무와 현장 기술 경험을 쌓도록 지원하는 독립형 데이터 플랫폼.

- 기준일: 2026-09-18 (최초 v1: 2026-09-17)
- 상태: 기획·디자인 기준안 v1. 제품 구현, 현장 협력, 모델 성능 및 고용 효과는 아직 검증하지 않았다.
- 기획 구분: 제조업 중심 v1. [소상공인 중심 v1](small-business/v1/PROJECT_PLAN.md)과 병렬 검토하며 두 안을 하나의 MVP로 합치지 않는다.

## 1. 해결하려는 문제

지역 중소 제조기업과 AI 기업·연구팀은 필요한 조건의 현장 데이터와 수집 파트너를 찾는 데 어려움이 있다는 가설에서 출발한다. 청년에게는 교육 이후 안전하고 유급인 실무 진입 경로가 필요하다. 다만 숙련 제조작업의 시연과 설비 설치·배포를 초급 청년이 곧바로 수행할 수 있다고 가정하지 않는다.

로보후드는 요청 목적, 현장·수행자, 검수된 데이터셋, 적용 결과와 재수집 요청을 연결한다. 수집 전문기업과 숙련 기술자는 계획·안전·품질·통합 책임을 맡고, 청년에게는 난도와 권한이 확인된 업무를 배정한다. 유료 데이터 수요와 일자리 효과는 인터뷰·실증으로 검증한다.

## 2. 이용자와 역할

| 참여자 | 요청하거나 제공하는 것 | 플랫폼에서 하는 일 |
|---|---|---|
| 제조기업·현장 담당자 | 개선할 공정, 수집 현장, 현장·데이터 이용 조건 | 과제 요청 또는 현장 제공, 출입·수집 범위 확인, 결과 검토 |
| AI 기업·연구팀 | 필요한 데이터의 조건과 활용 목적 | 데이터 수집 요청, 검수 기준 합의, 승인된 데이터의 평가·활용 |
| 데이터 수집 전문기업·팀 | 장비, 수집 계획, 현장 수행·검수 역량 | 과제 수락, 직무·숙련도별 배정·지도, 수집 품질 관리 |
| 청년 Physical AI 현장 전문인력 | 교육·숙련 수준에 맞는 현장 업무 | 배정된 수집·검수 보조 또는 승인된 기술지원, 수행 이력 축적 |

요청자, 현장 제공자, 수집 수행팀은 서로 다를 수 있다. 한 조직이 여러 역할을 맡을 수도 있으므로 과제별로 구분해 기록한다. 조직 유형만으로 데이터 소유권이나 접근권한을 부여하지 않는다.

‘청년 Physical AI 현장 전문인력’은 프로젝트의 상위 인력 명칭이다. **데이터 수집 오퍼레이터 / 현장 기술지원 인력 / FDE(현장 적용 엔지니어)**를 구분하며, 모두가 FDE이거나 순서대로 자동 승급하는 체계는 아니다. 직무·책임·진입 조건은 [운영 원칙](OPERATIONS.md#2-청년-직무와-일자리-품질)에 따른다.

## 3. 대상 현장과 첫 데모

- **대상:** 지방 산업단지 등을 포함한 지역 중소 제조기업·제조 소공인. 특정 지역만을 대상으로 한 서비스로 한정하지 않는다.
- **정책 범위:** 전국·지역 산업 기반의 기획이다. 서울 실증을 추진한다면 서울 제조 소공인·교육 공간 등 별도의 현장 근거를 확보해야 하며, 제조업 전체를 서울시 사업으로 표현하지 않는다.
- **실증 상태:** 첫 협력기업과 실증 지역은 미정이다. 전국 운영망이나 실제 공장 배포를 확보한 것으로 표현하지 않는다.
- **대표 데모:** 가상의 제조 현장에서 수행하는 ‘소형 부품 외관 검사’. 실제 업종·공정의 최종 선정과는 구분한다.

| 데모 항목 | v1 기준 |
|---|---|
| 요청자 / 현장 / 수행팀 | AI 연구팀 / 한빛 정밀 / 로컬 수집팀 — 모두 가상 예시 |
| 수집 데이터 | 안전한 모의 작업대의 부품 RGB 이미지, 전문가 기준에 따른 라벨 후보, 촬영·수집 조건 |
| 활용 목적 | 외관 결함 판별 모델의 평가·적용 가능성 확인 |
| 현장 반응 | 판별 결과를 LED·서보 등 소형 장치 또는 명시된 시뮬레이터로 전달 |
| 다시 모으는 데이터 | 실패 이미지, 검수 결과, 모델·장치 버전이 연결된 운영 이벤트 |

초급자의 첫 업무는 촬영·조건 기록·라벨 초안이며 최종 판정은 검수 담당자가 맡는다. 명장 기술의 재현, 가동 설비 조작·정비, 위험 공정 촬영은 기본 진입 업무에서 제외한다.

사람의 작업 영상, 시뮬레이션, 텔레오퍼레이션은 서로 다른 후속 수집 방식이다. 일반 RGB 검사 이미지·사람의 영상이 곧바로 RFM(Robot Foundation Model)의 로봇 행동 학습 데이터가 되는 것은 아니다. 목표 모델·로봇·입력 형식과 이용 권한부터 확인한다.

## 4. 핵심 제품 흐름

`데이터 요청 → 현장·직무 조건 확인 → 교육·수행팀 배정 → 유급 수집·검수 → 데이터셋 제공 → 전문기업의 적용 결과 → 재수집`

| 제품 영역 | 핵심 기능 |
|---|---|
| 과제·수행 연결 | 요청 목적, 제공 현장, 수집·검수 조건, 직무·교육·보상 조건, 수행팀 배정 |
| 데이터 관리 | 원본·가공 데이터, 라벨, 품질 기록, 이용 조건과 버전 관리 |
| 모델·장비 적용 | 전문기업이 수행한 평가·배포 이력 연결. 초급 수집 인력의 책임과 분리 |
| 운영·재수집 | 장치 상태와 실패 이벤트 확인, 원인 기록, 후속 수집 과제 생성 |

자체 수집·저장·조회 기능은 외부 데이터 플랫폼의 계정·API 없이 동작하도록 한다. KAMP 등 외부 서비스는 향후 선택적 가져오기·내보내기 대상이며, 필수 의존성이나 확정된 제휴가 아니다.

## 5. v1 MVP 경계

한 과제, 한 이미지 데이터셋, 교육·직무·보상 조건, 수집·검수와 재수집 버전을 우선 구현한다. 기존의 한 판별 모델·한 장치 또는 시뮬레이터 연결은 **적용 추적 데모**로 유지하되 숙련 기술 담당자의 영역으로 구분한다. 소상공인안과 달리 제조안은 이 적용 추적까지 검증한다.

RFM 신규 학습, 다수 공장의 자율 운영, 자동 최적 매칭, 데이터 거래·결제는 MVP에서 제외한다. 하드웨어가 없으면 시뮬레이터를 허용하되 실제 산업현장 배포와 구분한다. 세부 기능·수용 기준·대체 구현은 [MVP 구현 명세](MVP_SPEC.md)에서 관리한다.

## 6. 청년 일자리와 운영 방향

청년은 안전교육과 지도하에 저위험 수집 업무로 진입한다. 검수·현장 기술지원·FDE는 별도 역량과 채용 요건을 갖춘 경우의 직무 선택지다. 일자리의 질은 유급 작업시간·보상, 교육, 검수 품질, 재참여와 후속 직무 연결로 판단한다. 매칭 수나 교육 이수자 수를 고용 실적으로 대신하지 않는다.

요청 기업의 데이터 수집·검수 대가를 기본 비용 가설로 둔다. 설비 설치·통합·유지보수는 전문기업의 계약 업무이며 공공지원으로 대체하지 않는다. 지자체·교육기관에는 공동 장비·안전한 실습 공간·교육·초기 유급 실증 지원을 제안한다. 비용 부담자·수요·지원은 아직 미확정이다. 보상·책임 원칙은 [운영 문서](OPERATIONS.md), 검증 항목은 [통합 확인 표](MVP_SPEC.md#6-미정-사항--확인-방법)에서 관리한다.
