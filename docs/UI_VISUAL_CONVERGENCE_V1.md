# RoboHood v1 · 이미지 대비 구현 보완 기록

## 결과

2026-09-18, `assets/ui-concepts/refined-v1/`의 제조업 21개·소상공인 20개 활성 시안을 기준으로 실제 브라우저 화면을 반복 비교하고 HTML/CSS를 보완했다. **두 앱 모두 v1을 유지**하며 원본 이미지·Stitch 내보내기 파일은 변경하지 않았다.

화면별 열 구성, 사진·일러스트 영역, 카드 크기, 타이포그래피, 여백과 모바일 입력 배치를 맞추는 데 집중했다. 41개 화면을 시각적으로 점검했다. 픽셀 차이 측정에 따른 일치율이나 완전한 복제는 주장하지 않는다.

시각 보완 완료 당시에는 로컬에만 반영했다. 이후 같은 날 사용자 요청으로 [Vercel에 재배포](VERCEL_DEPLOYMENT_V1.md)했으며 화면 이동 메뉴의 설정 충돌도 수정했다. 아래 74개와 75개 검사는 각 시점의 이력이다. 후속 반응형·발표 흐름 보완은 자동 검사 91개와 production 82개 화면 점검을 통과했으며 Git `main`에도 반영했다.

## 이미지 사용 방식

- 사진과 역할 일러스트만 원본 PNG의 제한된 영역을 SVG `viewBox`로 표시한다. 이미지 자체를 다시 생성하거나 덮어쓰지 않는다.
- 텍스트·폼·버튼·필터·상태·내비게이션은 실제 HTML/JavaScript다. 전체 시안을 화면 배경으로 붙이고 클릭 영역을 덮은 구현이 아니다.
- 사진에 그려진 재생 버튼이 실제 기능처럼 보이지 않도록 소상공인 상세 화면의 사진 영역을 교체했다. 실제 영상 미리보기는 네이티브 파일 입력과 연결된 수집 화면에서만 제공한다.
- 이미지의 예시 승인·성과 수치를 복사하지 않고 현재 브라우저의 데모 기록을 표시한다.

주요 구현 파일은 `apps/refined/fidelity.mjs`, `fidelity-pages.mjs`, `fidelity.css`, `reference-art.mjs`다. 기존 공통 셸·상태 로직과 연결하며, `tests/fidelity.test.mjs`에서 화면별 구성·장식 이미지 범위·실제 입력 요소를 검사한다.

| 검증 | 확인 결과 |
|---|---|
| 빌드·자동 테스트 | 최종 `npm run check` **74/74 통과** |
| 원본 보존 | 원본 체크섬 및 활성 시안 41개와 빌드 이미지의 SHA-256 대응 검사 통과 |
| 반응형 | 41개 화면 × 320·375·768·1536px = **164회** 점검, 페이지 가로 넘침과 일반 이미지 요소 로드 오류 없음 |
| 시각 점검 | 전체 화면의 구성·아트워크를 확인하고 대표 데스크톱·470px 모바일 화면을 재확인 |
| 브라우저 로그 | 점검 중 수집된 콘솔 경고·오류 없음 |
| 수정 형식 | `git diff --check` 통과 |

자동 테스트는 시각 유사도 판정의 대체물이 아니다. 반응형의 일반 이미지 로드 검사는 SVG 내부 이미지 로드까지 증명하지 않으므로 SVG 아트워크는 화면에서도 확인했다. 스크린샷은 검증 과정에서 직접 열람했으며 별도 회귀 이미지 파일 묶음으로 저장하지 않았다.

### 직접 수행한 기능 회귀 확인

모든 입력·상태 변경은 `?qa=1`의 분리된 테스트 저장소에서 수행했다. 일반 데모 기록은 초기화하거나 변경하지 않았다.

- 제조업: 새 과제 등록 → 조건 4개 확인 시 시작 차단 → 5개 확인 후 시작 → RGB 기록 → 제출 → 검수 역할 전환 및 기준 확인 → 승인.
- 제조업: 이용 신청 후 검수 승인과 이용 신청 대기, 모의 지급 대기가 각각 유지됨을 확인했다.
- 소상공인: 새 과제 등록 → 조건 확인 → 구간 수집. 시작·끝이 같은 잘못된 구간은 거부하고 `0–8초` 구간은 정상 기록·제출했다.
- 소상공인: 수집 담당의 검수 승인을 차단하고 검수 담당 전환 후 승인했다. 검수 승인 후에도 이용 미승인·모의 지급 대기를 유지했다.
- 두 앱의 새 과제 제목 표시, 현장 필터에 따른 목록 감소, 지도 표시 전환을 확인했다.

## 의도적으로 시안과 다르게 남긴 부분

1. 실제 데모 데이터의 개수·상태·제목을 우선한다. 시안처럼 보이기 위해 과제 수·검수 결과·승인·지급을 꾸미지 않는다.
2. 촬영·안전·보상 조건, 수집과 검수의 분리, 이용 승인과 지급의 독립성을 유지한다.
3. 모바일에는 실제 입력·오류 안내·터치 영역이 필요해 시안보다 세로로 길어질 수 있다. 내용을 잘라 한 장에 억지로 맞추지 않는다.
4. 두 앱의 지도 마커는 모의 위치 예시이며 실제 사업장 위치·거리·모집을 나타내지 않는다. 네이버 지도를 불러오지 못하면 도식 지도를 표시한다. 예시 사진은 재생 가능한 영상으로 표시하지 않는다.
5. 화면별 사진·아이콘의 미세한 차이와 동적 기록에 따른 높이 차이는 남아 있다. 브라우저·서체별 픽셀 동일성은 검증하지 않았다.

## 다음 수정 시 반복 기준

대응하는 활성 시안을 열고 동일한 뷰포트에서 구현을 비교한다. 먼저 열 구조·큰 사진·카드 비율을 맞춘 뒤 제목·간격·색상·세부 요소를 조정한다. 수정 후 같은 화면을 다시 확인하고 320/375/768/1536px 가로 넘침 및 `npm run check`를 재검사한다. 사진에 포함된 장식과 실제 동작 요소를 혼동하지 않는다.

현재 결과는 프런트엔드 데모다. 이번 점검에서 로컬 영상 파일 선택·재생, 다운로드, 실기기·스크린리더·전반적인 접근성 적합성, 서버 연계까지 검증한 것은 아니다. 실제 인증·업로드·AI 판정·로봇 제어·고용·지급 완료를 의미하지 않는다.
