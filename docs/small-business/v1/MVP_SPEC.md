# RoboHood 소상공인 중심 MVP 구현 명세 v1

- 기준일: 2026-09-18
- 기준: [제품 기획서](PROJECT_PLAN.md) · [운영 원칙](OPERATIONS.md)
- 상태: 개발 요구사항 제안이며 구현·고용·데이터 구매 실적이 아니다. 제조업 중심 v1과 별도 범위다.

## 1. 대표 시나리오

가상의 로봇·AI 연구팀이 ‘트레이 위 컵 정리’ 영상의 작업 구간과 성공 여부를 확인할 수 있는 데이터를 요청한다. 모의 카페 현장을 등록하고, 교육·수집 조건·보상 조건에 동의한 청년 데이터 수집 오퍼레이터를 배정한다. 영상을 업로드하고 검수·보완한 뒤 승인된 버전과 수행 이력을 제공한다.

목표는 실제 영상 파일·명세·검수·권한·유급 작업 조건이 연결되는 흐름이다. 연구팀 구매 의사, 실제 학습 효과, 청년 실제 지급은 별도 검증한다.

## 2. 기능과 최소 데이터

| 단위 | 필수 기능·기록 |
|---|---|
| 데이터 요청 | 요청자, 사용 목적, 작업 정의, 대상 물체, 촬영·품질·수량 조건, 검수 기준, 비용 부담자 |
| 현장 | 지역, 업종·업무, 모의/실제 구분, 허용 구역·시간, 현장 책임자, 촬영·이용 조건 승인 상태 |
| 직무·배정 | 데이터 수집 직무, 필수 교육·과제별 평가, 감독자, 수락 상태, 예상 시간·보상·보완 조건 |
| 수집 세션 | 요청·현장·수행자·시각·장비, 원본 영상, 작업 구간, 성공/실패/판정 보류, 환경·변수 기록 |
| 검수 | 담당자, 품질 조건별 판정, 개인정보 노출 여부, 승인·반려 사유, 재제출 연결 |
| 데이터셋 버전 | 승인 세션 묶음, 이전 버전·출처, 파일·메타데이터, 이용 목적·권한·보관 조건 |
| 수행·보상 기록 | 실제 작업·준비·보완 시간, 합의 보상, 확인 주체, 지급 대기/확인, 실제/모의 구분 |

v1 원본에는 사람의 영상과 그 설명이 있고 로봇 관절·행동 명령 데이터는 없다. 해당 필드가 없는데 값으로 채우거나 로봇 행동 데이터로 표시하지 않는다. 텔레오퍼레이션·시뮬레이션은 별도 데이터 유형·수집 규격을 결정한 후 확장한다.

## 3. 상태와 권한

1. 요청자가 수집 목적·명세·비용 부담 조건을 등록한다.
2. 현장 제공자와 운영팀이 수집 허용·안전·보상·이용 조건을 확인한다.
3. 운영팀이 교육·과제별 적격 여부를 확인하고 수행자와 감독자를 배정한다.
4. 수행자가 조건을 수락한 뒤 수집 세션을 시작한다. 미승인·미이수 상태에서는 시작할 수 없다.
5. 수행자는 자신의 세션을 제출하고, 검수 담당자는 승인 또는 사유가 있는 보완 요청을 남긴다.
6. 승인 세션만 데이터셋 버전에 포함한다. 이용 승인을 받은 요청자만 조회·내보낼 수 있다.
7. 업무 종료와 지급 확인은 별도 상태로 기록한다. 검수 통과만으로 지급 완료 처리하지 않는다.

세션 상태: 배정 대기 → 조건 확인 → 수집 → 검수 → 승인 또는 보완 → 데이터 제공.
보상 상태: 조건 미합의 → 합의 → 지급 대기 → 지급 확인. 모의 데모에서는 모든 지급 상태에 ‘모의’를 표시한다.

## 4. 화면 구성 제안

아래 7개 기능 묶음을 [20개 페이지 시안](UI_SCREEN_PLAN.md)(데스크톱 15개·모바일 5개)으로 구체화했다. [갤러리](../../../assets/ui-concepts/small-business/v1/index.html)는 이미지 열람용이며 기능 구현이 아니다. 제조업 이미지와 별도 세트다.

| 화면 | 보여줄 내용·핵심 행동 |
|---|---|
| 서비스 소개·작업 공간 | 청년·소상공인·데이터 요청 기업·운영팀의 역할 |
| 현장 탐색 | 서울 생활권·업종·수집 가능 업무·협의 상태. 현장 상세 → 수집 요청 |
| 수집 과제·상세 | 작업 명세·영상 규격·품질 기준·예상 시간·보상·감독 |
| 교육·인력 배정 | 수집 직무·과제별 적격 여부·교육 이수·수락 상태 |
| 모바일 작업함·수집 | 준비 체크 → 영상 입력·작업 구간 → 제출·보완·중단 보고 |
| 검수·데이터셋 | 재생·구간 라벨·승인/반려, 버전·출처·이용 권한 |
| 수행·보상 이력 | 실제 작업시간·검증된 이수/수행 이력·실제/모의 지급 구분 |

모델·장비 카탈로그, 배포·관제는 첫 MVP 메뉴에서 제외한다. 후속 적용은 과제의 데이터 사용 목적·피드백 링크로 표현한다. 상세 지도·자동 매칭보다 실제 수집·검수·권한 흐름을 먼저 구현한다.

## 5. 수용 기준

| 검증 | 통과 조건·증거 |
|---|---|
| 한 과제 재현 | 요청 → 교육·배정 → 실제 샘플 영상 입력 → 반려·보완 → 승인 버전까지 연결 |
| 진입 조건 | 교육·수집 승인·감독·보상 미확인 상태의 수집 시작 거부 시험 |
| 실제 데이터 처리 | 업로드 영상 재생과 구간 라벨 저장·재조회. 파일명만 보여주는 모형과 구분 |
| 검수·버전 | 반려 사유·재제출·이전 버전 보존, 승인 데이터만 제공 |
| 권한·이용 조건 | 타 과제 무단 조회·내보내기 차단, 승인된 이용 목적·보관 조건 표시 |
| 노동·지급 구분 | 작업·보완 시간과 보상 조건 조회. 검수 완료와 실제 지급 확인을 별도 기록 |
| 과장 방지 | 모의 현장·기업·지급, 실제/가상 데이터를 표시. RFM 학습·실제 로봇 배포 완료 문구 없음 |

## 6. 미정 사항 / 확인 방법

| 미정 사항 | 확인 방법·진행 조건 |
|---|---|
| 실제 데이터 구매 수요 | 기업과 사용 목적·샘플 명세·합격 기준·비용 부담 의사를 확인. 일반 관심 표현을 발주로 간주하지 않음 |
| 첫 업무·현장 | 서울의 협력 매장 또는 모의 공간에서 안전·촬영 허용·업무 난도 확인 |
| 데이터의 학습 적합성 | 요청 기업에 소량 샘플 전달·평가. 영상만으로 로봇 제어 학습이 가능하다고 단정하지 않음 |
| 보상·운영비 | 청년의 준비·작업·보완 시간, 감독·장비·현장 제공 비용을 포함해 지속 가능성 검토 |
| 촬영·데이터 권리 | 수행자·현장 제공자·요청자의 동의 및 이용 범위, 고객·직원 노출 차단 검토 |
| 공공지원 | 교육·장비·실습 공간·초기 유급 실증 지원의 대상·예산·기간을 협의. 확보 전 확정 표현 금지 |
| 텔레오퍼레이션 확장 | 장비·숙련 감독자·교육·정지 조건·로봇 데이터 명세 확보 후 별도 과제 승인 |

첫 실제 배정은 수요 명세·현장 승인·교육 및 감독·보상·데이터 이용 조건이 모두 확인된 뒤에만 진행한다. 개발 단계에서는 가상 요청과 촬영 허용된 모의 데이터로 위 조건을 시험한다.
