## 설계 기준

대외 인력 명칭은 **청년 Physical AI 현장 전문인력**으로 통일한다. 첫 세부 직무는 현장 데이터 수집이다. 소상공인은 현장 제공자, 로봇·AI 기업은 데이터 요청자, 운영팀은 교육·감독·검수·보상 운영 주체로 나눠 표시한다.

대표 사례는 `RH-SB-001` 식당 테이블 정리·식기 분류와 `RH-SB-002` 동네마트 냉장상품 선입선출 진열이다. 두 과제 모두 고객이 없는 모의 환경에서 성인 수행자의 1인칭 작업 영상과 행동 구간을 기록한다. 화면 이미지는 생성된 가상 장면이며 실제 사업장이나 수집 실적이 아니다.

1. 수집 전에 교육·과제 적격, 현장 촬영 허용, 감독, 안전, 보상 조건을 확인한다.
2. 검수 결과·데이터 승인·지급 확인을 별도 상태로 표현한다. 지급 관련 표시는 모두 모의다.
3. 현장 제공 동의와 모델 학습·외부 공유 권한을 자동으로 연결하지 않는다.
4. 보완 사유와 작업 범위·시간·보상·이의 제기 경로를 함께 보여준다.
5. 설치·통합·배포를 초급 수집 인력의 책임이나 자동 승급으로 표현하지 않는다.

로봇·POS 구매, 음성 제어, 자체 RFM 학습, 로봇 배포·관제, 자동 결제·지급은 메뉴에서 제외한다. 텔레오퍼레이션·시뮬레이션은 후속 검토이며 이 세트의 완료 기능이 아니다.

## 역할별 흐름

- 데이터 요청 기업: 01 → 02 → 04 → 05 → 07 → 08 → 16 → 17 → 19.
- 소상공인·현장 제공자: 02 → 05에서 촬영·업무·현장 제공 조건 협의 → 08에서 참여 범위 확인.
- 수집 운영팀: 03 → 06 → 08 → 09 → 15 → 16·17 → 18. 19·20에서 별도 권한 관리.
- 청년 현장 전문인력: 10 교육·적격 → 11 작업함 → 12 진입 조건 → 13 영상·구간 제출 → 14 보완·문의 → 18 수행·보상 이력. 전 과정은 데스크톱 웹이며 모바일에서도 반응형으로 제공한다.
- 검수 담당: 15에서 승인 또는 보완 → 승인 데이터만 16·17에 포함. 본인이 수집한 세션을 자동 승인하는 권한은 부여하지 않는다.

이 연결은 구현할 흐름을 설명한다. 갤러리에서는 이미지만 확대·이동할 수 있으며 이미지 속 버튼은 작동하지 않는다.

## 화면별 핵심 상태

- 05: 현장 조건은 협의 중이다. 현장 지도·위치·협력 관계는 모두 예시다.
- 10: 교육 일부만 완료되어 실습·과제별 적격 확인이 남아 있다.
- 12: 보상·보완 조건이 미확인인 경우 시작 버튼을 비활성화한다.
- 13: 사용자가 선택한 로컬 영상을 브라우저에서만 미리 보고 구간 메타데이터를 기록한다. 서버 업로드나 카메라 수집 완료를 뜻하지 않는다.
- 14: 보완 조건 합의 전에는 재작업을 요구하지 않는다.
- 15: 품질 조건 미충족 세션의 승인 버튼은 비활성화한다.
- 17·19: 데이터 이용 조건·권한 승인 전에는 내보내기·이용 승인을 차단한다.
- 18: 준비·수집·보완 시간의 예시 기록과 모의 지급 대기 상태를 구분한다. 실제 고용·보상 실적이 아니다.

각 페이지는 서로 다른 시점의 예시 상태다. 화면의 숫자를 같은 시점의 데이터베이스 스냅샷으로 해석하지 않는다. 기획 버전 v1과 화면 속 데이터셋 v0.1도 별개다.

## 구현 우선순위와 미포함 범위

20개는 서비스 흐름을 검토하기 위한 주요 페이지 목록이지 20개 모두를 첫 MVP에서 완성한다는 약속이 아니다. **요청 명세 → 현장 조건 → 교육·배정 → 수집·검수 → 승인 버전·권한 → 수행·보상 기록**을 먼저 연결하고, 소개·탐색·지도·범용 설정은 단순화할 수 있다.

20개 페이지 모두 같은 반응형 웹 구조를 사용한다. 작은 화면에서는 사이드 메뉴를 서랍형으로 바꾸고 넓은 표를 라벨 카드로 재배치한다. 모든 모달·오류·역할별 변형을 별도 이미지로 만들지는 않았으며, 이미지 내부의 작은 문구·숫자가 구현 계약은 아니다. 충돌 시 제품 기획서와 MVP 명세를 우선한다.

## 보존과 버전

제조업 이미지와 문서는 유지한다. 활성 디자인 참고 이미지는 `assets/ui-concepts/refined-v1/small-business/`에 저장하고, 실제 기능과 반응형 동작은 `apps/` 소스와 배포 화면을 기준으로 검증한다. 이미지 수정이 필요하면 원본을 보존한 별도 파일을 만든다.
