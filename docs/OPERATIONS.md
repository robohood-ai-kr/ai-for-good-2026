# RoboHood 제조업 중심 운영 원칙 v1

- 기준일: 2026-09-18 (최초 v1: 2026-09-17)
- 기준: [제품 기획서](AI_FOR_GOOD_PROJECT_PLAN.md) · [MVP 구현 명세](MVP_SPEC.md)
- 상태: 현장 실증 전 운영 설계. 계약·협력·지원금·고용 조건이 확정된 것이 아니다.

## 1. 과제별 책임

| 참여자 | 책임으로 설계할 범위 |
|---|---|
| 요청자 | 활용 목적·필요 데이터·검수 조건 제시, 허용 범위 내 이용, 결과 확인 |
| 현장 제공자 | 현장 출입·수집 허용 범위, 안전 담당·보안 조건, 작업자 촬영 관련 확인 |
| 수집 전문기업·팀 | 수집 계획·장비 확인, 수행자 배정·지도, 품질 관리, 현장 문제 대응 |
| 청년 Physical AI 현장 전문인력 | 배정 직무의 교육·권한 범위 내 수행, 조건 기록, 이상 시 중단·보고 |
| 현장 기술지원 인력·FDE | 별도 자격·역량과 승인 범위의 장비 점검·통합·적용, 기술 책임 기록 |
| 검수 담당자 | 합의한 조건에 따른 승인·반려, 수정 사유·품질 이력 기록 |
| 플랫폼 운영자 | 과제·권한·데이터 이력 관리, 문의·사고 처리 경로 마련 |

같은 조직이 여러 역할을 맡을 수 있으나 책임을 구분해 기록한다. 과제 배정만으로 공장 출입, 설비 제어 또는 데이터 재이용 권한이 생기지 않는다. 역할별 법적·계약상 책임은 실제 협의와 검토 후 정한다.

## 2. 청년 직무와 일자리 품질

상위 명칭은 **청년 Physical AI 현장 전문인력**이다. 아래는 프로젝트의 역할 구분이며 공인 직종·자격 체계를 뜻하지 않는다. 제조업 설비 운전원과도 구분한다.

| 직무 | 맡는 업무 | 진입·책임 경계 |
|---|---|---|
| 데이터 수집 오퍼레이터 | 촬영·조건 기록·라벨 초안, 승인된 프로토콜의 시연·텔레오퍼레이션 | 교육·과제별 평가·감독 필요. 초급 기본 업무는 저위험 촬영·기록이며 최종 검수·설비 조작 권한 없음 |
| 현장 기술지원 인력 | 수집 장비 설치·점검, 연동·배포 보조, 승인된 유지보수 | 장비별 교육·기술 역량·별도 작업 승인 필요. 제조설비 정비를 기본 업무로 두지 않음 |
| FDE · 현장 적용 엔지니어 | 요구 정의, 데이터·모델·장비 통합 설계, 현장 적용과 기술 문제 해결 | 개발·통합 경험과 책임 범위가 필요한 전문 직무. 초급 청년 일자리로 일괄 배정하지 않음 |

세 직무는 자동 승급 단계가 아니다. 초급자는 안전한 모의 작업대에서 시작하며 명장 작업 재현·가동 설비 조작은 제외한다. 텔레오퍼레이션은 대상 로봇·업무·감독·정지 조건을 확인한 별도 실습으로 검토한다.

- 안전·보안·데이터 윤리와 장비 사용 교육을 과제 배정의 전제로 삼는다.
- 초급자는 책임자의 지도 범위에서 수행하고, 위험하거나 권한을 벗어난 작업을 중단·보고할 수 있어야 한다.
- 건당 수집량뿐 아니라 준비·교육·검수·보완 업무를 고려해 유급 업무와 보상을 설계한다.
- 수행 이력은 과제, 맡은 역할, 확인한 기술, 교육 이수, 검수 결과 등 확인 가능한 기록으로 남긴다.
- 자체 이수·경력 기록을 공인 자격증이나 보장된 취업으로 표현하지 않는다.
- 희망자에게 추가 교육·역량 검증을 거쳐 검수, 현장 기술지원 또는 지역 제조기업 취업으로 연결할 선택지를 제공한다. FDE 전환을 보장하지 않는다.

지급 단가, 계약 형태, 보험·사고 책임, 청년의 참여 조건은 아직 정하지 않았다. 고용 규모와 지역 정착 효과 역시 검증 전 가설이다.

## 3. 데이터 권리와 안전

| 시점 | 확인할 내용 |
|---|---|
| 수집 전 | 제공자의 권한, 수집 목적·장소·대상, 작업자 관련 동의·거부 처리, 안전·영업기밀 범위 |
| 수집 중 | 필요한 범위만 수집, 노출 위험 기록, 승인되지 않은 촬영·장비 제어 중단 |
| 저장·검수 | 원본·가공 데이터와 출처 구분, 불필요한 식별정보 제거, 과제별 접근권한 |
| 활용·반출 | 조회·평가·학습·재배포의 허용 범위, 외부 공유 승인, 이용 이력 |
| 보관 종료 | 합의한 기간과 삭제·보존 예외, 원본·파생물의 처리 범위 확인 |

데이터 소유권은 조직 유형이나 업로드 행위로 자동 결정하지 않는다. 제공자·수집자·요청자의 이용 범위와 권한을 구분한다. ‘자체 데이터 플랫폼’은 모든 데이터의 공개·거래·소유를 뜻하지 않는다.

데모는 가상 조직과 촬영 허용된 샘플을 사용한다. 실제 개인정보·공장 영상·영업기밀을 공개 저장소, 화면 시안, 생성 프롬프트에 넣지 않는다. 실제 운영 전 계약·안전·개인정보 요건을 확인한다.

## 4. 지역 지원과 교육기관의 역할

지자체에는 실증현장 발굴, 공동 장비·안전한 테스트베드, 교육·초기 유급 실증 및 지역기업 취업 연계를 제안한다. 일상적인 납품·설치·연동·유지보수는 전문기업의 계약 업무로 구분하고 청년 지원사업이 그 비용·책임을 대신하도록 설계하지 않는다. 전국 제조업 수요와 특정 지자체의 지원 대상·범위를 구분하며, 서울 사업을 제안한다면 서울 현장·참여 청년·지원기관을 별도로 확인한다.

유급 수집·검수의 기본 비용 부담자는 데이터 요청 기업이라는 가설이다. 현장 제공 대가·장비비·감독비·청년 보상을 분리해 협의한다. 공공 실증 지원은 한시적인 진입 지원 가설이며 예산·제휴·지속적인 유료 수요가 확보된 것은 아니다.

교육기관에는 센서·데이터·로봇 기초, 산업안전·데이터 윤리, 모의 제조환경 실습, 지도하의 현장 연계를 제안한다. 미성년 학생의 교내 모의실습과 실제 산업현장 참여는 구분하고, 관련 요건을 확인하기 전 현장 투입을 전제하지 않는다.

## 5. 실증 운영에서 확인할 것

실증 시작 전 요청 목적·수집 허용·직무별 수행 책임·안전·보상·이용 조건을 확인한다. 종료 후에는 실제 유급 작업시간·지급 확인, 교육·보완 소요시간, 검수 통과율, 재참여, 장치 적용 문제와 후속 직무 가능성을 기록한다. 시뮬레이션 보상 기록과 실제 지급은 구분한다.

정량 목표나 성과는 측정 방법·분모·기간을 정한 후 사용한다. 만족도·일자리 수·비용 절감 효과를 데모 화면의 예시 수치로 대신하지 않는다.

미정 사항과 확인 방법은 중복 목록을 만들지 않고 [MVP 통합 확인 표](MVP_SPEC.md#6-미정-사항--확인-방법)에서 관리한다.
