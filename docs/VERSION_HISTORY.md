# RoboHood 기획·디자인 버전 기록

이 문서의 버전은 기획과 화면 시안의 기준이다. 소프트웨어 릴리스·현장 배포·성능 검증 버전과 구분한다.

## 현재 기준 — 두 기획안 모두 v1 / 2026-09-18

| 기획안 | 목적·범위 | 문서·화면 |
|---|---|---|
| 제조업 중심 v1 | 지역 제조현장 데이터 수집과 전문기업의 적용·재수집 연결 | 기획서·MVP·운영 원칙, 새 생성 시안 21개와 별도 실행 앱 |
| 소상공인 중심 v1 | 서울의 소상공인 현장·모의 매장과 청년 유급 수집 업무 연결 | [별도 기획서](small-business/v1/PROJECT_PLAN.md)·[MVP](small-business/v1/MVP_SPEC.md)·[운영 원칙](small-business/v1/OPERATIONS.md), 새 생성 시안 20개와 별도 실행 앱 |

사용자 요청에 따라 두 안은 각각 v1이다. 소상공인안은 제조업안의 후속 v2나 기존 POS·음성 제어 통합안이 아니다. 이후 버전 번호도 기획안별로 관리한다.

### 이미지 장점 종합 및 image-to-code — 같은 v1

- 기존 이미지의 쉬운 설명·단일 과제 흐름과 Stitch의 정보 구조·파란색 운영 UI를 결합했다. [새 시안 41개](../assets/ui-concepts/refined-v1/index.html)와 본문용 생성 사진 2개를 별도 경로에 저장했다.
- 내장 image_gen으로 화면별 생성 및 문구·배경 보완을 수행하고 프롬프트·출처 manifest를 보존했다. 이전 이미지·Stitch HTML/PNG는 변경하지 않았다.
- 새 시안의 배치와 DESIGN.md의 색상·간격·글자 기준을 `apps/refined/`의 HTML/CSS 컴포넌트로 옮겼다. PNG를 화면 전체 배경으로 붙이는 방식이 아니다.
- 두 앱의 메뉴·저장소·데이터 유형은 분리했다. 제조업은 RGB 수집·FDE 모의 적용, 소상공인은 1인칭 영상의 구간 기록·검수·수행 및 보상 확인에 집중한다.
- 조건 미충족 시 시작 차단, 잘못된 영상 구간 거부, 검수 항목 확인, 검수·이용 승인·지급 상태 분리를 연결했다. 서버 인증·업로드·AI·실제 로봇·지급 구현은 포함하지 않는다.
- 현재 검증 범위와 남은 제약은 [구현 안내](UI_REFINEMENT_V1.md)에 기록했다. 이는 v2나 외부 배포·성능·고용 성과 검증 릴리스가 아니다.

### 이미지 대비 반복 보완 — 같은 v1

- 제조업 21개·소상공인 20개 활성 시안과 실제 브라우저 화면을 비교하며 화면별 열 구조·사진·역할 일러스트·타이포그래피·여백·모바일 입력 배치를 보완했다.
- 원본 이미지의 사진·장식 부분만 SVG로 표시하고, 텍스트·폼·버튼·필터·상태는 실제 HTML/JavaScript로 유지했다. 동적 수치와 승인·지급 상태를 시안 값으로 덮어쓰지 않았다.
- 최종 자동 검사 74/74 통과, 41개 화면 × 4개 너비의 164회 반응형 점검에서 페이지 가로 넘침을 발견하지 않았다. 수집 조건·구간 입력·역할별 검수·이용 승인 분리도 테스트 저장소에서 확인했다.
- 원본·v1 명칭은 유지하며 이번 변경은 로컬 빌드에만 반영했다. 자세한 검증 범위와 의도적인 차이는 [시각 보완 기록](UI_VISUAL_CONVERGENCE_V1.md)에 남겼다.

### 시각 보완본 공개 재배포 — 같은 v1

- 이후 사용자 요청으로 시각 보완본을 기존 `robohood-v1` Vercel 프로젝트와 공개 주소에 반영했다.
- 공개 점검에서 발견한 화면 이동 메뉴의 모바일 목록/현재 화면 여부 충돌을 수정하고 회귀 테스트를 추가했다. 최종 자동 검사 75개, 두 앱의 메뉴 목록·검색·주요 링크 확인을 통과했다.
- 공개 정적 파일 98개 접근, 텍스트 파일 55개 해시 일치, 제외 경로 9개 404를 확인했다. 이전 배포는 보존했으며 Git 커밋·푸시·Supabase 연결은 수행하지 않았다. [배포 기록](VERCEL_DEPLOYMENT_V1.md)

### 발표·반응형 준비 최종 보완 — 같은 v1

- 청년용 화면을 모바일 고정형이 아닌 데스크톱 우선 반응형 웹으로 통일했다. 좁은 화면에서는 메뉴 서랍과 표 카드 전환을 사용하며, 숨긴 메뉴는 키보드·보조 기술의 탐색 대상에서도 제외한다.
- 소상공인 대표 흐름을 `청년 수집·제출 → 웹 독립 검수 → 운영팀 승인·지급 반영 → 청년 수행 이력`의 3단계, 34초 발표자 모드로 연결했다.
- 화면의 `v1` 표기와 오해하기 쉬운 텔레오퍼레이션 현재 기능 문구를 제거하고, 텔레오퍼레이션은 로봇 상태·행동·시간 동기화와 안전 조건이 필요한 후속 실증으로 구분했다.
- 자동 검사 91개를 통과했다. production의 제조업 21개·소상공인 20개 화면을 데스크톱과 모바일에서 총 82회 확인하여 런타임 오류·페이지 가로 넘침·표 넘침을 발견하지 않았다. 소상공인 네이버 지도와 3단계 상태 전환도 별도로 확인했다.
- 앱 코드와 기획 문서를 Git `main`에 커밋·푸시하고 production을 재배포했다. 현재 배포와 검증 범위는 [배포 기록](VERCEL_DEPLOYMENT_V1.md)을 따른다.

### 제조업 현장 탐색 지도 정렬 — 같은 v1

- 제조업 21번 현장 탐색에도 소상공인 화면과 같은 네이버 지도 연동, 필터·지도 좌측 패널, 현장 목록 우측 패널을 적용했다. 공개 Client ID가 없거나 지도 로드에 실패하면 기존 도식 지도를 유지한다.
- 서울·대전·부산 권역의 세 마커는 실제 사업장이나 모집 현황이 아닌 모의 위치 예시로 표시한다. 대표 모의 현장에는 수집 안전 조건과 상세·요청 연결을 제공하고, 나머지는 조건 미정 상태로 둔다.
- 제조업 사이드바 왼쪽 아래의 금속 부품 장식 이미지는 제거해 소상공인 화면처럼 문구와 현장 작업 링크만 남겼다.

### 공통 디자인 기준 — MUI + KRDS / 같은 v1

- 사용자 선택에 따라 [DESIGN.md](../DESIGN.md)에 MUI의 대시보드 구성과 KRDS의 한글 가독성·색상 역할·접근성 원칙을 결합했다.
- 파랑·청회색·흰색의 RoboHood 전용 토큰, 타이포그래피, 반응형 배치, 컴포넌트·상태·검증 기준을 정리했다. HEX는 제품 제안값이며 공식 KRDS 토큰 복제나 이미지 추출값이 아니다.
- 제조업과 소상공인은 시각 기준만 공유한다. 기능·메뉴·권한과 두 기획의 v1 버전은 유지한다.
- 기존 초록색 PNG·프롬프트·갤러리는 변경하지 않았다. 실제 화면 구현·접근성 검증·라이브러리 채택을 완료한 것은 아니다.

### 명칭과 팀 피드백 반영

- 상위 명칭을 ‘청년 Physical AI 현장 전문인력’으로 통일했다. 데이터 수집 오퍼레이터·현장 기술지원 인력·FDE의 직무·권한·진입 조건을 구분했다.
- 제조업안에서 초급 업무를 저위험 촬영·기록·라벨 초안으로 좁혔다. 명장 작업·설비 조작·전문 설치와 통합을 초급자의 책임으로 두지 않았다.
- 전국·지역 제조업과 서울 생활권 실증의 정책 범위를 분리했다. 공공의 교육·실증 지원과 민간기업의 설치·유지보수 책임을 구분했다.
- 두 안에 데이터 구매 수요·비용 부담자, 유급 작업·보상·감독 조건, 실제 지급과 모의 기록의 구분을 반영했다.
- 소상공인안은 요청 기업·현장·청년 수집 인력의 역할을 분리하고 1인칭 작업 영상 한 가지부터 검증하도록 구성했다. 텔레오퍼레이션·시뮬레이션은 별도 조건을 갖춘 후속 후보다.

### 이미지 글자만 수정

AI 이미지 생성·재생성 없이 Swift/AppKit으로 지정된 글자 영역만 수정했다. 기존 PNG는 보존하고 `assets/ui-concepts/v1/text-overlays/`에 별도 수정본을 만들었다. [변경 명세](../assets/ui-concepts/v1/text-overlay-manifest.json)와 [픽셀 비교 기록](../assets/ui-concepts/v1/text-overlay-report.json)을 남겼다.

01·07·18에는 상위 명칭을, 메뉴에는 ‘현장 인력’을 사용한다. 수집 담당과 배포 담당을 구분하고 자동 승급처럼 보이던 경력 문구를 수정했다. 08은 변경할 명칭이 없어 유지했다. 갤러리에서 수정 전후를 비교할 수 있다. 교육·권한·보상 요구사항을 실제 제품 기능으로 구현했다는 의미는 아니다.

### 소상공인 페이지별 이미지 생성 — 같은 v1

- 새 [소상공인 갤러리](../assets/ui-concepts/small-business/v1/index.html)에 데스크톱 15개·모바일 5개, 총 20개 시안을 별도 생성했다.
- 제조업 이미지의 색상·타이포그래피만 참고하고, 현장·과제·교육·감독·유급 수집·검수·접근권한·수행 이력 중심으로 내용을 새로 구성했다.
- 보상 조건 미확인 시 수집 시작 차단, 보완 사유·조건 확인, 승인 데이터만 제공, 검수와 모의 지급 분리를 화면에 표현했다.
- 내장 image_gen을 사용했으며 [페이지별 프롬프트](../assets/ui-concepts/small-business/v1/prompts.json)를 보존한다. 기존 제조업 PNG는 변경하지 않았다.
- 이미지 속 영상 장면은 가상이며 실제 영상 처리·현장 배정·고용·지급 기능이 구현된 것은 아니다. 각 화면은 서로 다른 시점의 예시다.

### 이번에 정리한 내용

- 요청자, 현장 제공자, 수집 수행팀, 청년 오퍼레이터를 구분했다.
- 지역 제조업을 대상으로 하되 실증 지역·협력사는 미정으로 남겼다.
- 소형 부품 RGB 이미지와 정상·불량 라벨을 외관 판별 평가에 쓰는 대표 데모를 구체화했다.
- 제품 설명·구현 명세·운영 원칙을 분리하고 반복 설명과 발표 준비용 표현을 정리했다.
- 결정사항·가정·위험을 한 확인 표로 통합했다.
- UI 20개 중 역할·과제 조건·데이터 이용 범위에 영향을 받는 8개를 보완하고 12개는 유지했다.

### 현장 탐색 화면 추가 — 같은 v1

- 21번 현장 탐색을 추가했다. 지도·현장 목록·선택 현장 상세를 함께 보여주고 데이터셋 조회와 수집 요청으로 연결하는 화면이다.
- 기존 제조공장 콘셉트 이미지에서는 지도·목록 배치만 참고했다. 정부 기관 표시와 실적 수치는 가져오지 않고 RoboHood 스타일과 예시 현장을 사용했다.
- 현재 활성 화면은 21개(데스크톱 18개·모바일 3개)다. 기존 20개 시안과 제품의 제조업 범위는 유지했다. 소상공인·청년 데이터 수집 중심으로 바꾸는 방안은 검토 단계이며 이번 추가에 포함하지 않았다.
- 실제 지도, 현장 매칭, 수집 요청 기능의 구현을 뜻하지 않는다. 상세 입력은 [21번 생성 프롬프트](../assets/ui-concepts/v1/21-field-explorer-prompt.json)에 기록했다.

### UI 원본 보존

최초 생성한 20개 PNG와 [초기 프롬프트](../assets/ui-concepts/v1/prompts.json)는 유지한다. 수정한 8개는 같은 v1 폴더의 `*-aligned.png`로 별도 저장하며 갤러리는 보완본을 우선 사용한다. 정확한 편집 입력은 [보완 프롬프트](../assets/ui-concepts/v1/alignment-prompts.json)에 있다. 보완 전 PNG는 참고 이력이며 현재 화면 기준이 아니다.

### 다음 변경 시

제조업 중심과 소상공인 중심을 구분해 변경점을 기록한다. 이후 버전 변경이 필요하면 사용자와 기준을 정하며, 현재 두 안은 모두 v1로 유지한다. 기존 이미지·프롬프트는 보존하고 수정본을 별도 경로에 둔다. Git 태그·커밋·공개 릴리스가 자동으로 생성된다는 뜻은 아니다.
