# RoboHood 🤖

현장의 일을 Physical AI 데이터로 만들고, 청년의 수행 경험을 지역 기술 일자리로 연결하는 현장 데이터 플랫폼입니다.

RoboHood는 데이터 요청부터 현장 조건 확인, 청년 현장 전문인력의 수집, 독립 검수, 데이터셋 승인, 현장 적용과 재수집까지 하나의 흐름으로 보여주는 웹 프로토타입입니다. 소상공인 중심 서비스와 제조업 중심 서비스를 각각 독립된 시나리오로 제공합니다.

## 공개 데모

| 대상 | 링크 | 대표 흐름 |
|---|---|---|
| 앱 선택 | [RoboHood](https://robohood-v1.vercel.app/) | 두 서비스 진입 |
| 소상공인 중심 | [운영 화면](https://robohood-v1.vercel.app/small-business/sb-03.html) | 과제 등록 → 청년 수집 → 검수 → 데이터셋·수행 이력 |
| 제조업 중심 | [운영 화면](https://robohood-v1.vercel.app/manufacturing/mf-03.html) | RGB 수집 → 검수 → 데이터셋 → FDE 적용·재수집 |

공개 화면은 데스크톱 웹을 기본으로 하며, 작은 화면에서는 반응형으로 동작합니다.

## 두 가지 서비스

| 구분 | 소상공인 중심 | 제조업 중심 |
|---|---|---|
| 대상 현장 | 식당, 동네마트 등 생활권 현장 | 지역 중소 제조기업·제조 소공인 |
| 대표 사례 | 식당 식기 분류, 냉장상품 선입선출 진열 | 소형 부품 외관 검사 RGB 이미지 수집 |
| 청년 역할 | 교육 후 허용된 작업 영상과 구간 기록 수집 | 안전한 작업대에서 RGB 촬영·라벨 초안 기록 |
| 전문 역할 | 운영·검수 담당 | 독립 검수 담당, 현장 적용 FDE |
| 핵심 결과 | 검수된 작업 데이터와 수행·보상 이력 | 출처·버전이 연결된 데이터셋과 적용·재수집 기록 |

두 서비스 모두 다음 원칙을 공유합니다.

- 수집 담당과 검수 담당을 분리합니다.
- 현장 촬영 허용과 데이터 이용 승인을 별도 단계로 관리합니다.
- 교육·안전·수행 범위·시간·보상 조건을 수집 전에 확인합니다.
- 청년 현장 전문인력과 FDE를 서로 다른 직무로 구분합니다.
- 목 데이터라도 과제 등록, 수집, 제출, 승인 상태가 실제 화면에서 변경되도록 구현합니다.

## 로컬 실행

Node.js 22 이상이 필요합니다.

```bash
npm ci
npm run dev
```

빌드 후 기본 주소는 `http://127.0.0.1:4173/`입니다.

| 명령 | 용도 |
|---|---|
| `npm run build` | 두 서비스 정적 빌드 |
| `npm run build:small-business` | 소상공인 화면만 빌드 |
| `npm run build:manufacturing` | 제조업 화면만 빌드 |
| `npm test` | 자동 테스트 실행 |
| `npm run check` | 전체 빌드 후 테스트 |
| `npm run deploy:prepare` | 검증 후 Vercel 배포 산출물 준비 |

## 현재 구현 범위

현재 결과물은 발표와 사용 흐름 검증을 위한 프런트엔드 프로토타입입니다.

- 실제 로그인·서버 파일 업로드·AI 추론·로봇 제어·결제·지급은 연결되어 있지 않습니다.
- 화면의 현장 조건 확인은 수집 과제를 설계하기 위한 절차이며, 자동화 가능성을 자동 판정하는 진단 기능이 아닙니다.
- 첫 수집 방식은 1인칭 작업 영상과 행동 구간 기록입니다. 텔레오퍼레이션은 로봇 상태·행동·시간 동기화와 안전 조건을 갖춘 후속 실증 범위입니다.
- 입력한 진행 상태는 브라우저 로컬 저장소에 보관되며 두 서비스의 상태는 분리됩니다.
- 예시 현장명, 위치, 수치와 생성 이미지는 실제 사업장·성과·협약을 의미하지 않습니다.
- 로컬 영상 미리보기는 서버로 전송하거나 저장하지 않습니다.
- 실제 개인정보나 민감한 현장 데이터를 입력하는 운영 서비스로 사용하지 않습니다.
